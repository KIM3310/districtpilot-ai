# Service Package - districtpilot-ai

This package defines the most practical service shape for this repository. It is public-safe: no price promises, financial projections, or buyer-specific contract assumptions are published here.

## Buyer and Wedge

- **Service lane:** Civic operations forecasting
- **Primary buyer:** Local governments, field-service planners, civic analytics teams, and district operators
- **Front-door offer:** District planning dashboard pilot
- **Service outcome:** Turn public or approved datasets into action cards, forecast evidence, and procurement-friendly review notes.

## Build and Polish Priorities

- Polish deployment/cost guidance without public estimates
- Clarify sponsor versus synthetic data boundaries
- Add action-card acceptance criteria

## Buyer-Ready Deliverables

- Dataset review
- Forecast evidence pack
- Planning dashboard pilot

## Activation Path

1. Use the public demo, README, screenshots, and tests to establish proof.
2. Confirm the buyer workflow, data boundary, owner, and acceptance criteria.
3. Build only the smallest workflow needed to prove the service outcome.
4. Add cloud resources, accounts, storage, or paid integrations only after the workflow boundary is approved.

## Margin and Risk Controls

- Keep compute paused outside review and connect managed resources only after a pilot owner is identified.
- Keep the first service scope narrow, repeatable, and evidence-led.
- Keep private financial planning outside the public repository.
- Keep logs, analytics, and reports free of private payloads unless explicit approval exists.

## Portfolio Signal

The portfolio should present this repository as **District planning dashboard pilot** under the **Civic operations forecasting** lane, with proof links routed to the live demo or repository evidence.
